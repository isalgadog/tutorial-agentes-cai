# Rúbrica de evaluación

## Challenge de la Sesión 2

Esta rúbrica sirve para evaluar si la arquitectura propuesta es simple, coherente y suficiente para una primera versión del agente.

## Escala sugerida

- 1 = deficiente
- 2 = débil
- 3 = aceptable
- 4 = sólido
- 5 = excelente

---

## 1. Claridad de componentes

Se evalúa si la propuesta distingue claramente frontend, orquestador, modelo, herramientas y datos.

## 2. Simplicidad arquitectónica

Se evalúa si el diseño evita complejidad innecesaria para una primera versión.

## 3. Coherencia con el producto

Se evalúa si la arquitectura responde al alcance definido en la sesión 1 y no introduce piezas que el producto todavía no necesita.

## 4. Manejo de herramientas y permisos

Se evalúa si las herramientas habilitadas son razonables y si se controlan acciones sensibles.

## 5. Claridad del flujo de información

Se evalúa si el flujo entre usuario, frontend, orquestador, modelo y herramientas es entendible y operable.

## 6. Distinción entre memoria y datos

Se evalúa si el diseño evita mezclar memoria conversacional con datos de negocio o persistencia sensible.

## Criterio de aprobación sugerido

El diseño está listo para pasar a la siguiente sesión si:
- tiene componentes mínimos bien definidos
- evita complejidad prematura
- mantiene coherencia con el producto
- controla razonablemente herramientas y flujo de datos
